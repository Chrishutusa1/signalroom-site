## What this is

This repo is the public website for **The Signal Room** (https://signalroompodcast.com), a healthcare-AI podcast hosted by Christopher Hutchins and produced by Hutchins Data Strategy Consultants (HDSC). The audience is healthcare executives (CMIOs, CISOs, data leaders). The site exists for three reasons, in priority order:

1. **SEO / AEO discoverability** — rank for healthcare-AI queries and get cited by AI answer engines (ChatGPT, Perplexity, Google AI Overviews). A large fraction of all commits are SEO work: canonical URLs, JSON-LD schema, meta-length trims, internal linking, IndexNow pings.
2. **Episode archive** — one standalone page per episode (34 as of July 2026) with embedded YouTube video, show notes, full transcript, FAQ schema, and guest sidebar.
3. **Guest funnel** — the `/be-a-guest` application form feeds Airtable and triggers notifications/auto-replies.

There is no application here in the framework sense. It is a **hand-authored static HTML site with zero build step**, plus a handful of Python maintenance scripts and one Netlify serverless function.

## The canonical-URL contract (load-bearing, do not casually change)

Documented and live-verified in `CANONICALIZATION-VERIFIED.md`:

- **Host:** apex `signalroompodcast.com`, https. `www` is a Netlify alias that 301s to apex; `_redirects` line 9 is a belt-and-suspenders duplicate of that.
- **Form:** extensionless (`/episodes/foo`, never `/episodes/foo.html`). Netlify `pretty_urls` handles serving; `_redirects` **enumerates an explicit `/<page>.html → /<page> 301!` line for every single page** because splat wildcards don't reliably match suffix patterns.
- **Articles:** lowercase `/articles/...` URLs rewritten (status 200) to the capital `/Articles/*.html` files.
- Every page carries a self-referential extensionless `<link rel="canonical">`, and `og:url` + JSON-LD `url` match it.
- **When you add a page you must do three things:** add the `_redirects` `.html → extensionless 301!` line, set the self-canonical, add an extensionless `<loc>` to `sitemap.xml`. All manual.

## Episode page anatomy

Each `episodes/<slug>.html` contains, in order: canonical + meta (description ≤155 chars, title ≤57 chars — hard publish gates), OG tags with `og:image` = the YouTube `maxresdefault.jpg`, the deferred GA4 loader, three JSON-LD blocks (`PodcastEpisode`, `FAQPage` with 2 curated Q&As, `BreadcrumbList`), nav, hero, YouTube iframe embed, info card with listen links (Apple/Spotify/Buzzsprout), long show-notes block, guest sidebar with hardcoded LinkedIn link, optionally a **shorts/clips carousel** (injected later by a separate cloud pass, not present at creation), a `<details>` full transcript (speaker-labeled), Beehiiv newsletter CTA, footer, and inline nav JS. Inline `style=""` attributes are used heavily inside episode content; the shared stylesheet covers chrome/layout.

## Key design decisions and their reasoning

1. **No templating/build system.** Shared chrome (nav, footer, GA block, fonts block) is duplicated into every one of ~57 HTML files. The trade-off is deliberate: any page can be patched independently by regex-driven scripts and cloud routines, and there is nothing to build or break. The cost is drift (three different `style.css?v=` values exist across pages right now) and site-wide edits requiring rollout scripts.
2. **Regex over parsers.** Every generator/validator parses HTML with regular expressions anchored to exact class names and attribute layouts (`class="guest-card-name"`, `data-short-title="..."`, JSON-LD field order). This works because the same scripts also *emit* that HTML. Consequence: **reformatting existing HTML blocks can silently break the scripts** — treat existing markup patterns as an API.
3. **Dry-run by default, `--apply` to act.** Every mutating script follows this convention. Preserve it in anything new.
4. **Publish gates are numeric and absolute.** Meta description ≤155 chars, title ≤57 chars. Recent git history shows repeated commits trimming to these caps; they're enforced by `_validate_episode.py`.
5. **Two-site deploy model.** Git push → staging auto-deploy; production is a **manual** `netlify deploy --prod` of the working directory. Production content is whatever was on disk when someone deployed — git main and prod can diverge in either direction.
6. **Analytics correctness over data volume.** GA4 loads only after idle/first-interaction AND only on the production hostname. Never "simplify" this back to a plain script tag.
7. **Cache aggressively, bust manually.** `netlify.toml` sets 1-year immutable caching on `/css/*` and `/js/*`; HTML gets 1h browser / deploy-invalidated CDN. Any CSS change is invisible on pages that don't get their `?v=` query bumped.
8. **YouTube thumbnail rule.** Episode card/OG thumbnails must be the real YouTube `maxresdefault.jpg` — never generated or substituted (explicit owner preference, enforced in commit a465fa1).

## Critical paths (ranked)

**Most load-bearing — change only with the full checklist:**
- `_redirects` — the entire canonical-URL contract. A bad line can loop or 404 the whole site.
- `sitemap.xml` — manual; all 34 episodes currently present; search consoles read this.
- `netlify.toml` — headers/caching/functions wiring.
- Episode-page `<head>` blocks (canonical, meta lengths, JSON-LD) — this is the product.
- `netlify/functions/submission-created.js` — the only server-side code; loses leads if broken (though Netlify Forms keeps a copy).

**Load-bearing but scripted — don't hand-edit what a script owns:**
- Homepage stat counters and Featured Guests block (`_update_stats.py` / `_update_featured_guests.py` own these; hand edits get overwritten).
- Topic-page episode grids (`_generate_topic_cards.py` owns these).
- Shorts-carousel alts (normalize script owns empty ones).

**Safe to change casually:**
- Copy inside show-notes/about/FAQ prose (keep meta-length gates in mind if you touch `<head>`).
- `css/style.css` (but bump `?v=` everywhere — see GAPS.md #4).
- `data/*.csv` (informational snapshots, nothing reads them at runtime).

## Things that will trip up someone new

- **`Articles/` vs `/articles/`** — capital-A on disk, lowercase in URLs. Never link to `/Articles/...` in an `href`; never lowercase the directory name.
- **Four critical scripts are invisible to git** (`git status` shows clean while `_validate_episode.py` etc. sit untracked because of `/*.py` in `.gitignore`).
- **The shorts carousel doesn't exist on a fresh episode page.** It's injected by a *later* cloud pass after clips are cut. Its absence is not a bug.
- **The cloud "add-podcast-episode" routine is not in this repo** and can't be edited from here; the local scripts are guards against its known defects (empty alts, no IndexNow ping).
- **Prod ≠ git main automatically.** Check both before assuming a change is live.
- **`js/linkedin-links.js`** is only loaded by `guests.html`, `index.html`, and the Articles pages — episode pages hardcode their sidebar LinkedIn link instead. The JS map (25 names) has not kept up with the guest roster (31+).
- **There is another well-known "Chris Hutchins"** (personal-finance podcaster). The site's Person schema carries a `disambiguatingDescription` for exactly this reason (commit b8a...). Don't remove it.
- The Wikidata entity for the show is `Q139555656`, referenced in the homepage `PodcastSeries` JSON-LD.
- The stray file `1577c9c65cc397ca183ed80f92e0f9cf.txt` at root is the **IndexNow key file** — it must stay, exactly named, containing exactly the key.
